# 21: Mask secrets in Events

**What to build:** `baton hook` masks secrets in the payload before the Event is written, so the archive (D7) never holds a token that an Agent printed or a command carried. A v2 item of DESIGN.md ("secret masking"), done first because retention (22) removes old files but cannot help with a secret that sits in a recent one.

**Blocked by:** none

**Status:** done

- [x] A new package `foundation/redact` that knows nothing about Baton: given a list of literal secrets it replaces, in a string, every literal of at least 8 characters and every match of the built-in patterns with `[REDACTED]`. Patterns: PEM private key blocks (`-----BEGIN ... PRIVATE KEY-----` to the matching END line, or to the end of the string when it is cut); `Bearer <token>`; well-known token shapes (`sk-ant-…`, `sk-…` of 20+ characters, `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`/`github_pat_`, `glpat-`, `xox[abprs]-`, `AKIA` + 16 capitals/digits, `AIza` + 35 characters, JWT `eyJ….….…`, Telegram bot token `\d{8,10}:[A-Za-z0-9_-]{35}`); and the value of an assignment whose name contains `token`, `secret`, `password`, `passwd`, `api_key`/`api-key`/`apikey` or `private_key` (any case), written `NAME=value`, `NAME: value` or `"NAME": "value"` (the name stays, only the value goes). Longer literals are replaced before shorter ones that they contain.
- [x] `Record` walks the payload as JSON and masks every string value (not keys, not numbers) with it; the structure and every non-string value are unchanged. A payload where nothing was masked is written byte for byte as it came. A payload where something was masked is re-encoded, so key order and spacing may differ; the Event then carries `"masked": true` (a new optional field of Event version 1, absent when nothing was masked). The `cwd` and `session_id` the Event keeps outside the payload are not masked.
- [x] The literals are the values of `~/.config/baton/secrets.env` (the same file and reader as `baton sync`, `foundation/secretsenv`). A hook that cannot read it (missing, refused because others can read it, malformed, or inside a container where it is not mounted) uses the patterns only, silently: it never fails, never prints and never quotes a line of that file. The patterns alone must be enough for the tests of the container Runtimes.
- [x] Secrets are masked in what later readers see too: a Handoff's "last commands" for a `Bash` command that carried a secret shows `[REDACTED]` (it is read from the masked payload; no change to the Handoff code is expected, a test proves it).
- [x] Tested at the binary seam only (AGENTS.md): `baton hook claude …` with payloads that carry each pattern and a literal from `secrets.env`; assert on the Event file. Also: nothing masked → file line identical to what was written before this ticket; the structure of a masked payload parses and keeps its non-string values; a `secrets.env` readable by others does not stop the hook and its values are then not used; a secret in a sandbox/compose-runtime hook is masked by pattern; Handoff commands show the mask.
- [x] `DESIGN.md`: D7 says what is masked, where (at write, hooks only), what is not (anything a human or the Agent wrote before the hook ran, the Agents' own session files, Events written before this ticket, a secret that fits no pattern and is not in `secrets.env`), and that the archive is therefore "raw except for secrets". Move "secret masking" in the v2 table to what is done; keep "retention" there until ticket 22. Add the new `masked` field to the Event format. Facts not verified are marked `[unverified]`.
