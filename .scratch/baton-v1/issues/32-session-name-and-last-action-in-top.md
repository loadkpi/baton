# 32: Session name and last action in `baton top`

**What to build:** `baton top` shows, for every Session, the name the Agent gave it and what it did last, so the user can tell Sessions apart without opening their tabs.

**Blocked by:** 31

**Status:** done

**Why.** Asked by the user right after `baton top` was tried live. Both Agents name their Sessions themselves (checked on Oct 27, 2026): Claude Code 2.1.311 appends `{"type":"ai-title","aiTitle":"<name>","sessionId":"<id>"}` lines to the Session's transcript (`transcript_path` of every hook payload; a transcript can be several MB, and the title is repeated, the newest one counts; a `custom-title` type may exist for a name the user set [unverified]); Codex 0.162.1 keeps `{"id":"<session id>","thread_name":"<name>","updated_at":...}` lines in `$CODEX_HOME/session_index.jsonl`.

- [x] **Name.** For a Claude Session: the newest `custom-title` (if any) else the newest `ai-title` of its transcript, found by reading the transcript from its end in bounded chunks (never the whole file into memory; give up after a bounded amount, e.g. 4 MB, and fall back). For a Codex Session: the newest `thread_name` line for its id in the Profile's `session_index.jsonl`. Paths inside a sandbox are mapped to the host the way the sandbox Runtime maps them already; a Compose Session (files inside the container or a volume) is not read. Fallback in every case where no name is found: the first `UserPromptSubmit` prompt of the Event file, on one line. Nothing is written anywhere. This is the one place Baton reads an Agent's own session files; DESIGN.md says so and why (read-only, one field, with a fallback), next to the line that says Baton does not parse them.
- [x] **Last action.** From the newest Event of the Event file, one short line: `PreToolUse`/`PostToolUse`/`PostToolUseFailure` → `<tool>: <command or file_path or pattern or url>` (the first that exists in `tool_input`; `Skill` → `skill <name>`; `failed` added for a failure), `PermissionRequest` → `asks: <tool>: ...`, `UserPromptSubmit` → `prompt: <prompt>`, `Stop` → `done`, `Interrupt` → `interrupted`, `SessionStart` → `started`, `SessionEnd` → `ended`; plus how long ago (`12s`, `4m`, `3h`, `2d`). Text is on one line (newlines become spaces) and is taken from the masked Event, so no secret appears.
- [x] **Layout.** `baton top` gets two columns, NAME and LAST, after SESSION; they take the room that is left and are cut with `…`. Under 100 columns LAST moves to a second, dimmed line under the selected row only. `baton ls` is unchanged (its output is scripted against), but it gets `--long` that adds NAME and LAST as columns.
- [x] **Cost.** Names are cached in memory by Session for the life of `baton top` and re-read only when the transcript's or index's size or modification time changed; the last action comes from the Event already read for the status.
- [x] Tested at the binary seam: a Claude transcript fixture with several `ai-title` lines (the newest wins) placed at the `transcript_path` of the payload, larger than one read chunk; a Codex `session_index.jsonl` in the Profile; a sandbox Session's index under `.ai-sandbox/home/.codex`; the fallback to the first prompt; each kind of last action; a secret in a command shown masked; `ls --long`; narrow and wide `top`.
- [x] README: the new columns in the `baton top` row and `ls --long`. DESIGN.md: the `baton top` section and the native-files exception.
