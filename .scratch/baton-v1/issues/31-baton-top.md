# 31: `baton top`

**What to build:** a live, full-screen table of the Sessions in the terminal, from which the user jumps to a Session's Guake tab or ends a stuck Session. The first step towards one place to see and drive everything, without the v2 daemon or a web UI.

**Blocked by:** 27, 28

**Status:** done (checked live by the user in Guake 3.10, Oct 27, 2026: the table, Enter switching to the Session's tab, `q` restoring the terminal)

**Why.** After ticket 27 the user asked for a single UI; v1 has `baton ls` and notifications only. Guake's D-Bus interface (checked live, Guake 3.10) has `get_tab_count`, `get_tab_name(i)`, `select_tab(i)` and `show`, and a tab that Baton titled with `-r` keeps that title while Claude Code runs (an untitled tab follows the title the Agent sets, for example `◐ <first prompt>`). So a Session that `baton new` or `baton handoff` started can be found by its tab title.

- [x] `baton top [--interval 2s]` needs a terminal on stdin and stdout; otherwise it says so and exits 2. It switches to the alternate screen, puts the terminal in raw mode, hides the cursor, and restores all of it on every way out (`q`, Ctrl-C, SIGTERM, an error). No dependency beyond the standard library unless one is justified in DESIGN.md (raw mode through `ioctl` on Linux is enough; the tests already make a pseudo-terminal with the standard library).
- [x] The table has the columns of `baton ls` and is read the same way (`sessionbus.List` through the same code as `ls`), redrawn every interval and on a key. `waiting_approval` and `lost` stand out (reverse video or colour that works without colour too, e.g. a marker column). Sessions are ordered as in `baton ls`. A header line says how many Sessions wait for the user; a footer shows the keys and the last message.
- [x] Keys: `↑`/`↓` and `k`/`j` move the selection, which stays on the same Session across redraws while it exists. `Enter` jumps: Baton looks for the Guake tab whose name is the title the Session's tab was given (`<project>/<task>:<agent>`, with the Task's name or its id, whichever the launch used; trying both is fine), then `select_tab` and `show`. No such tab (a Session started by hand, a closed tab, Guake not running) → a footer message saying so; nothing else happens. `e` ends the selected Session as `baton session end` would, after a `y/N` question in the footer; a running Session is refused with the same message as `session end` (no `--force` from `top`). `q` quits.
- [x] Guake is reached with `gdbus call --session --dest org.guake3.RemoteControl --object-path /org/guake3/RemoteControl --method org.guake3.RemoteControl.<method> ...`, parsing its `('text',)` / `(3,)` output; `gdbus` missing or failing is a footer message. The tab lookup lives behind the Terminal (launchguake or a sibling store), not in `app`.
- [x] Tested at the binary seam through the pseudo-terminal harness (`env.StartTerminal`): the table and its markers; the selection moving and surviving a redraw when a Session appears; `Enter` with a matching tab (a `gdbus` stub with tab names records `select_tab <i>` and `show`), with no matching tab, with `gdbus` missing; `e` then `y` ends an unjudgeable Session, `e` then `n` does not, `e` on a running one is refused; `q` restores the terminal (the alternate-screen exit sequence is written); no terminal → exit 2.
- [x] README: a row for `baton top`. DESIGN.md: a short section (what it reads, the tab lookup by title and why it cannot find Sessions started by hand, that it is not the v2 dashboard).
